# Session retro — 2026-07-26 — 5624909c

## Focus

Session ouverte sur BUG-1, dérivée vers l'outillage qualité au fil des demandes :
dépendances, grammaire du générateur d'entités, bascule du linter, doctrine de
délégation aux sous-agents.

## Fait

- **BUG-1 instruit** : la garde du mode machine (`commander.opts().json`) ne
  s'exécutait JAMAIS — `--json` est déclaré par la sous-commande. Prouvé par sonde
  dans le code compilé. Le symptôme d'origine ne se reproduit plus ; un banc de
  bout en bout le refuse désormais. BUG-1 reste ouvert, honnêtement.
- **Dépendances** : 106 alertes fermées par le retrait de six verrous fossiles
  (un an, `pm2` encore dedans), 26 paquets montés, React Router 7 → 8 (le paquet
  `react-router-dom` n'existe plus en v8), rolldown 1.2.0, pilote SQLite 13.
- **Grammaire d'entités** : index de table composites (`--index`, `--unique`,
  répétables), tailles de colonne (`string(n)`, `char(n)`, `decimal(p,s)`), et la
  référence porte enfin le TYPE de la clé visée.
- **Banc devkit** : une étape neuve juge la cohérence FK ↔ PK.
- **Linter** : eslint → oxlint (aucune règle typée n'était utilisée), CI qui lance
  enfin le lint, configuration CodeQL, scaffold d'application aligné.
- **Doctrine de délégation** : `AGENTS.md` créé, `CLAUDE.md` durci.

## Coûts évidents

- **Deux incidents de concurrence agents/principal** — un travail non commité
  emporté, puis des fichiers corrompus. Les deux ont coûté une restauration
  complète et une re-vérification.
- Montée TypeScript 7 : 1 h 40 de run pour un verdict négatif. Utile malgré tout
  (voir plus bas), mais le blocage était identifiable plus tôt.
- Beaucoup de chantiers en parallèle sur le même dépôt — le user l'a fait
  remarquer, à raison.

## Recommandations

1. **Reprendre les 142 erreurs de lint autrement** : par catégorie, avec un
   automate quand il existe, et l'édition gardée par l'agent principal.
2. **Rendre le lint bloquant en CI** une fois le compte à zéro (retirer
   `continue-on-error`).
3. **Traiter l'alerte ReDoS `Route.ts`** — la seule jugée réelle sur les sept.
   Le correctif proposé deux fois (`(.*)` → `(.*?)`) n'est PAS équivalent : il
   change ce qui est capturé. À valider par les tests de routage.

## Patterns récurrents (déjà gérés)
