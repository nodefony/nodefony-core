## Épilogue — la passe d'ÉVALUATION, et ce qu'elle a montré

Après la construction, l'agent a été chargé d'évaluer le framework avant adoption.
Il a lancé de lui-même `npm audit`, `npm run verify`, `nodefony doctor --live`,
puis `--deep`. Verdict croisé, au même instant sur la même application :

| Commande         | Résultat                                                            |
| ---------------- | ------------------------------------------------------------------- |
| `npm audit`      | **0 vulnérabilité**                                                 |
| `npm run verify` | **exit 1** — arrêté sur `THIRD-PARTY-NOTICES.md`, AVANT les tests   |
| `doctor --live`  | **✓ RIEN À SIGNALER**                                               |
| `doctor --deep`  | **✓ RIEN À SIGNALER**, après avoir annoncé qu'il lançait les gardes |

Deux enseignements, tous deux vérifiés dans le transcript :

- **Le premier geste d'un évaluateur bute sur un fichier que le framework a
  généré lui-même.** `verify` s'arrête au format, donc l'évaluateur ne voit même
  pas le reste. C'est l'argument décisif pour l'alpha.6.
- **`--deep` lance QUATRE gardes** (`typecheck`, `lint`, `test`, `npm outdated`)
  et saute `format:check` — exactement celle qui échoue. Un mode dont la raison
  d'être est d'exécuter les gardes rend un vert sur un projet dont `verify` sort
  en erreur. → #364.

À noter aussi : l'agent a employé `doctor --live` et `--deep` sans que le fichier
d'instructions de son application les nomme (la modification de ce jour n'est pas
publiée). Il les a découverts dans la SORTIE de `doctor`, qui les propose en
« À FAIRE ENSUITE ». Deuxième confirmation du jour que la sortie d'une commande
enseigne là où une page ne se lit pas.
