## Le seul constat produit

Le banc de tenue dans la durée, sur 16 minutes : **tas V8 plat** (0,4 MB, sous le bruit du GC),
**handles stables**, débit stable — mais **RSS +77,9 MB/h, R² 0,99, sans plateau**, dont 105 %
de « reste » (hors V8 : fragmentation, piles, natif non rattaché). Soit +1,96 MB par million de
requêtes, grandeur transposable. Le banc refuse de trancher sous 90 minutes et le dit ;
un run de 90 min a été lancé en travail de nuit.

## Coûts évidents

  une mesure la fausse sans que le chiffre le dise. D'où une session largement séquentielle.

## Recommandations

1. **`nodefony-test-session`** — créé cette session : la matrice des étages, ce qu'un run vert ne
   prouve pas, et l'arbre de décision d'un rouge. Ce qui manquait n'était aucune recette, c'était
   leur ORDRE.
2. **Les délais en dur des bancs** (#63, #104) — c'est le poste qui produit le plus de faux rouges.
3. **Purger l'état partagé avant une passe** — le keyspace Redis grossit d'un run à l'autre.
