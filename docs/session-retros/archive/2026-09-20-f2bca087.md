## Frictions

- 🔴 **J'ai failli retirer huit scripts npm qu'un test protégeait par une MESURE** (`nodefony doctor`
  employé 5 fois sur 63 au banc de découvrabilité). Le manifeste est le canal de découvrabilité des
  commandes, pas une redite de la CLI. Deux tests sont tombés — le filet a marché, mais je ne
  l'avais pas lu avant de trancher. C'est le user qui a alerté, deux fois.
- 🔴 **Ma contre-épreuve ne mesurait rien** : elle réordonnait l'information au lieu de la retirer.
  Corrigé, versé dans [[feedback_gate_must_bite]].
- 🔴 **Ticket ouvert sans chercher de doublon** — le user a dû poser la question. Le contrôle coûtait
  une commande.
- ⚙️ **Un import de script l'a EXÉCUTÉ** (deux runs d'agent payés pour rien) — le piège est déjà
  gradué, [[feedback_script_import_executes]] ; il a mordu quand même.
- 🧾 **Le hook pre-commit a refusé deux commits** (fiches de skills périmées, renvois morts, banc non
  acquitté) : trois défauts réels, tous attrapés avant d'entrer.
- 👻 **Un shell bloqué depuis 16 h** (un `rg` d'une session antérieure) signalé par le user, pas par
  moi.

## Coûts évidents

- Le user a dit **stop** sur la dépense pendant #440 : le banc était le ticket demandé, mais son
  coût n'avait pas été annoncé à l'ouverture. **À énoncer avant de commencer un ticket d'outillage.**
- Trois bancs/suites lourdes lancées : `verify-generated` (21 étapes), le lot d'auto-contrôles du
  banc devkit (44), et 4 runs d'agent (2 sondes manuelles + 2 du banc).

## Recommandations

1. **Annoncer le coût d'un ticket d'outillage AVANT de l'ouvrir** — un banc, même demandé, se chiffre
   en séance.
2. **Lire les tests d'un gabarit avant de le simplifier** : ils portent des mesures, pas des goûts.
3. **Chercher le doublon avant d'ouvrir un ticket** — une commande, systématiquement.
