## Frictions / leçons

- **Co-évolution ratée** : changer un contrat backend (verrouiller `/nodefony/*/api`) **sans adapter le
  consommateur** (Studio) a cassé le login — silencieusement (build/tests verts). Le ping `/health`
  pré-login + la socket connectée au boot anonyme tapaient le data plane gaté → 401/boucle.
- **L'intégration > l'unit pour un PONT inter-briques** (point du user, répété) : l'unit était 100 % vert,
  mais l'intégration + le navigateur ont révélé **3 bugs** que l'unit ne pouvait pas voir : `handshake.url`
  absolue (matcher de zone jamais résolu), close WS **1011 au lieu de 1008** (boucle de reco client),
  **liveness gatée** (ping pré-login 401).
- **Liveness = PUBLIC** : Zero Trust protège les DONNÉES, pas la liveness. `/health`/`/info` doivent être
  publics (sondes k8s + ping pré-login). Une aire data plane large ne doit pas les avaler.
- **Close WS d'un refus d'auth = 1008 (Policy), jamais 1011 (Internal)** : 1011 → le RealtimeClient
  reconnecte en boucle ; 1008 → il abandonne proprement. `renderWebsocket` faisait `code<1000→1011`.
- **Décorateur sans argument = SANS parenthèses** (`@BypassFirewall`, pas `@BypassFirewall()`) : un drapeau
  n'est pas une factory. Dual classe+méthode calqué sur `@Domain` (lu au montage, ordre indifférent).
- **Session valide pour protéger une WS** (validé user) : le cookie présenté au handshake = authentification
  de CONNEXION, pas un login-over-WS. Login reste HTTP.
