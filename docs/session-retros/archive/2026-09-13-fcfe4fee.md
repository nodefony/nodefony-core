## Fait

**Publication `10.0.0-alpha.6`** (#369 fermé). Chaîne complète verte, 6/6 jobs,
aucun sauté. Accueil basculé à la main (`d4cc5f3a`) : la bascule automatique vit

**Le bug du « manifeste vide »** (#386, corrigé par `1a8e0dcf`). `nodefony dev`
échouait systématiquement là où `npm run dev` réussissait, sur la même
application. Cause : la délégation au CLI local se fait par `import()` dans le
même process, donc `process.argv[1]` restait le binaire tapé ; le superviseur
relance le serveur par `spawn(execPath, argv.slice(1))` et repartait sur l'autre
paquet ; deux instances de `nodefony` en mémoire ; la marque `Symbol()` de
`defineConfig` illisible d'une instance à l'autre ; repli muet sur
`defaultAppConfig` dont `modules` vaut `[]`.

Trois étages, chacun vu mordre : `alignArgvWithDelegate` (la cause),
`Symbol.for` (immunité), `isForeignDescriptor` + avertissement (l'app démarre
quand même, et l'écart est annoncé).

**Banc de la matrice de lancement** : les 4 voies (`nodefony dev`, `npm run
dev`, `npx`, `.bin/`) bootent à l'identique — vu ROUGE sans le correctif (seule
la première tombe), vert avec.

## Coûts évidents

- **Quatre causes annoncées avant d'être mesurées**, toutes fausses : `dist` en
  cours d'écriture, course build/boot, instances concurrentes, environnement du
  user. Chacune a coûté un cycle de build + un test.
- **Le décor du user sali par mes propres mesures** : `npm run dev` lancé puis
  tué dans SON dossier → `dist` amputé → son lancement suivant échoue → j'ai
  présenté cet échec comme une confirmation.
- **Un `dist` injecté périmé**, bâti avant la dernière correction du message.
  Vu seulement en comptant les occurrences dans l'artefact reçu (`0`).
- **`PATH` forcé à `/usr/bin:/bin`** plusieurs fois → `node`, `npm`, `gh`
  introuvables, trois commandes perdues.
- **Monitor `jq` mort trois fois** sur des lignes malformées ; relancé deux fois
  à l'identique avant de changer d'outil (boucle `case` en shell pur).

## Recommandations

1. **Demander la commande EXACTE avant de chercher dans le code** quand un
   symptôme n'est pas reproductible — la différence était `nodefony dev` vs
   `npm run dev`, et rien dans le dépôt ne pouvait la révéler.
2. **Ne jamais mesurer dans le dossier où le user travaille** — reproduire sur
   une copie à soi, systématiquement.
3. **Un message d'erreur est une affirmation sur le runtime** : le vérifier en
   l'exécutant avant de le livrer (celui-ci était faux, attrapé de justesse).
