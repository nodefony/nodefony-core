récupération possible. Le dépôt lui-même est intact (reflog vérifié, aucun process orphelin) ;
la perte est côté utilisateur.

**Ce qui est grave n'est pas le coût en tokens, c'est la PERTE DE CONTRÔLE.** Un agent que j'ai
lancé a occupé le canal entre le user et moi, et la seule parade qui lui restait — une deuxième
instance sur le même dépôt — est destructrice par nature : deux Claude Code sur le même arbre se

## Ce que la session a trouvé, et qui valait le détour

- **`Module;` seul dans deux constructeurs de serveur** n'est pas un oubli : c'est le seul usage
  de `Module` comme VALEUR dans ces fichiers, et sans lui le bundler élide l'import — or
  `design:paramtypes` est compilé en `typeof Module === "undefined" ? Object : Module`.
  L'injection recevrait `Object`, **sans rien lever**. Un nettoyage l'aurait cassée.
- **Les `.d.ts` du cœur survivaient à leur source** : le générateur n'efface pas ce qu'il ne
  produit plus, et le cœur était le seul paquet sans `rimraf dist` en tête de build. Pire, le
  cache du gestionnaire de tâches archive le CONTENU du dossier de sortie → une construction
  faite sur un dossier sali empoisonne l'empreinte, et le `clean` suivant est annulé par la
  restauration. Des types morts partaient chez l'installeur.
- **165 tests Mongoose étaient muets** faute de variable d'infra, conteneur pourtant sain
  depuis trois jours. Le piège que `CLAUDE.md` documente, vérifié une fois de plus.
- **TypeScript 7** : le blocage a changé de nature sans que personne le note. Plus
  `typescript-eslint` (parti avec eslint), mais **Angular 22** et **typedoc**, sur leurs
