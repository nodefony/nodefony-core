## Coûts évidents

- **Beaucoup d'allers-retours sur un symptôme mal nommé.** « Un timeout tue la commande » a orienté
  la recherche vers des délais inexistants ; le discriminant était dans la phrase suivante du user
  (« sur le menu ça tient »). Lire l'observation ENTIÈRE avant de partir sur la première hypothèse.
- **Deux commits refusés par commitlint** (en-tête > 100 caractères) — réécrire un message de 60
  lignes pour un titre trop long coûte plus que de le compter avant.
- **Un build oublié** avant un commit : le hook exige `dist` construit, l'échec arrive après le
  message. Enchaîner build → commit quand le diff touche le cœur.

## Ce que la session a appris

- Un symptôme qui ressemble à un délai peut être un event loop qui se vide : chercher ce qui
  RETIENT le process, pas ce qui le tue.
- Un défaut vit souvent en deux exemplaires ; corriger l'un laisse l'autre, et les deux passent
  leurs propres tests.
- Deux gardes qui se ressemblent ne répondent pas à la même question (traversée ≠ périmètre ;
  identité prouvée ≠ droits effectifs).
- Composer une assertion de chemin ne suffit pas : il faut composer avec la même opération que le
  code juge.
