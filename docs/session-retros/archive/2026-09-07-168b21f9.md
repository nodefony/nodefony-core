## Frictions (versées dans RETEX.md, sous des thèmes existants)

- `--publish` sortait en 0 sans rien publier — la répétition avalait le drapeau (🪤).
- Le gate de dépôt a menti deux fois : `npm query` rend l'arbre installé, puis mon sabotage visait
  `devDependencies` au lieu de `peerDependencies` (🟢).
- Les pairs internes en `*` faisaient installer la 7.0.2 — le seul chemin éprouvé (app générée)
  masquait le défaut (🚪).
- `man/nodefony.1` est générée, commitée, publiée, et jamais régénérée à l'estampillage (🚧).
- `npm publish` noie la demande du code 2FA sous 800 lignes de `notice` par paquet (🪟).

## Coûts évidents

- Trois lancements de la publication avant qu'elle parte : deux avalés par le défaut de mode, un
  arrêté faute de TTY (le `!` du prompt Claude Code n'ouvre pas d'entrée interactive — la
  publication a été lancée depuis un vrai terminal, avec `script` pour capturer).
- Deux instruments faux d'affilée sur la même vérification (le gate), donc trois cycles de
  sabotage/restauration avant une preuve valable.
- Un alignement trop large qui a cassé `npm install` du dépôt (`@nodefony/llm` épinglé alors qu'il
  n'est pas publié), constaté puis restauré.

## Recommandations

1. Ne jamais conclure d'un `npm view` juste après une publication — le document agrégé propage en
   ~2 min et le cache local de npm ment ensuite (`--prefer-online`).
2. Toute règle de MODE d'un script irréversible va dans le cœur pur, avec ses tests.
3. Avant de croire un gate neuf : prouver le débranchement sur le CHAMP exact, par `git diff`.

## Patterns récurrents (déjà gérés)

- ✅ « Prouver sur l'artefact reçu » — c'est ce qui a fait ouvrir le tarball et interroger le
  registre plutôt que le dépôt.
- ✅ « Un gate qu'on n'a jamais vu échouer n'est pas un gate » — appliqué quatre fois, et c'est ce
  qui a démasqué les deux instruments faux.
