## Le fil : trois preuves qui n'existaient pas

Le Dockerfile ne vivait que dans un dossier d'exemple que le plan voulait
supprimer : personne générant une app n'en recevait. Il est devenu un gabarit
(deux presets), prouvé sur une app **générée** — `pid: 1` constaté, requête de
2 s drainée pendant `docker stop`, exit 0.

Puis le smoke a cessé de copier ce dossier : il installe `nodefony` **depuis son
tarball** et laisse ce binaire produire ses applications témoins. Les gabarits
sont donc éprouvés tels qu'ils sont PUBLIÉS — un fichier oublié dans `files` ne
se voit d'aucune autre façon. Le dossier figé a pu partir ensuite (R3).
