## Coûts évidents

- **Un dist TROMPEUR a coûté quatre tours de vérification** — le serveur servait `index-BGQKR7ka.js`
  quand le build venait de produire `index-BKsQEmTa.js`. J'ai soupçonné mon code trois fois avant de
  comparer le bundle SERVI au bundle BÂTI, ce qui répond en deux `grep`. Trois mécanismes conjugués :
  `build:ui` ne purge pas, `turbo` restaure un dist caché par-dessus, `PrebuiltUi` ne lit
  `index.html` qu'au démarrage.
- **Six clients MCP écrits à la main** pour finir sur le même `404 Session not found`. C'est LE
  poste de dépense de la session, et il était évitable : le conteneur imprime la config à coller
  dans ses journaux dès le premier `docker logs`. L'agent d'audit a trouvé la cause en lisant le
  code du serveur : un heartbeat que le client doit honorer, sinon le serveur ferme la session.
- Trois allers-retours sur une capture d'écran périmée (Playwright n'écrase pas un fichier
  existant) avant de penser à regarder le `mtime`.
- Deux cycles `build:ui` + redémarrage serveur pour basculer entre `vite` et `static`.

## Recommandations

1. **Brancher un serveur MCP au harnais AVANT d'écrire la moindre ligne de client** — la règle
   « chercher qui porte déjà la capacité » vaut aussi pour les protocoles, pas seulement le code.
2. **Une sonde doit distinguer « je n'ai pas pu mesurer » de « c'est faux »** — sinon elle accuse
   le sujet à la place de son propre canal.
3. Ne pas livrer une capacité dans un GABARIT avant de l'avoir exercée de bout en bout : ici la
   spec est allée dans `AGENTS.md` alors que le contrôle des écrans n'était pas prouvé.
