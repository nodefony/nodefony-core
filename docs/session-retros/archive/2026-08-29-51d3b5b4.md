## Ce qui a été trouvé — quatre faux positifs silencieux

Aucun n'était exercé par un test, et chacun rend le code du succès :

1. `--up-to <tag inconnu>` adoptait **tout** l'historique.
2. `--source <inconnue>` rendait « rien à réparer » sans rien toucher.
3. Un `.sql` annoncé par le journal mais absent remontait un `ENOENT` nu.
4. **`NF_MIGRATE_DATABASE_URL` était jetée en silence sur un connecteur sqlite** —
   un job de déploiement migrait une base locale éphémère et rendait 0.

Plus deux pièges d'encodage payés par Windows (marque d'ordre des octets comptée
dans l'empreinte ; ligne à deux tirets DANS une chaîne littérale prise pour un
commentaire), la couleur des commandes qui n'honorait ni `NO_COLOR` ni
`FORCE_COLOR`, et le repli `?? 5151` de quatre gabarits de test.

## Coûts évidents

- **Le décor de la MACHINE, deux fois.** Un superviseur de dev orphelin tenant
  `127.0.0.1:5151` a fait rendre 404 à toute la suite d'une application générée ;
  et l'écriture de fichiers pendant qu'un run tournait a produit un rouge que
  j'ai failli m'attribuer. Les deux se sont réglés en rejouant ISOLÉ.
- **Quatre rebuilds `--force`** pour que le CLI charge le `dist` corrigé — le
  cache turbo a déjà servi un artefact d'avant un débranchement dans une session
  précédente, donc l'empreinte est cherchée DANS le dist à chaque fois.
- **Le rapport HTML refait quatre fois** : contraste, accès clavier, refus
  affichés vides, puis couleurs absentes. Chaque défaut n'était visible qu'en
  REGARDANT la page.

## Recommandations

1. **Pour tout drapeau de commande : écrire le COUPLE** (refus sans lui, travail
   avec lui). C'est ce qui a rendu quatre défauts visibles en une passe, là où
   des tests de chemin heureux n'en voyaient aucun.
2. **Capturer les écrans RÉELS d'une commande est un instrument de revue**, pas
   un livrable cosmétique : deux défauts produit ont été trouvés par là, dont le
   plus grave de la chaîne.
3. **Compter les séquences ANSI d'une capture censée être colorée** avant de
   conclure quoi que ce soit sur un affichage.

## Patterns récurrents (déjà gérés)

- ✅ Suspecter son propre diff : fait deux fois, et les deux fois la comparaison
  (plans de génération identiques, run isolé vert) a innocenté le diff.
- ✅ Gate vu mordre : cinq débranchements, chacun prouvé par `grep` sur le
  fichier avant relance.
- ✅ Prouver sur l'artefact reçu : empreinte cherchée dans le `dist` après chaque
  rebuild, application réellement générée puis lancée.
