## Ce que l'exercice a démenti

**Le contrat du noyau client portait quatre défauts**, et l'ordre dans lequel ils sont tombés est
l'enseignement : trois en écrivant l'implémentation (registre typé sur une interface qui ne pouvait
pas nourrir le fournisseur React ; aucune porte d'entrée pour l'identité, donc D9 inapplicable ;
un membre `log` masquant la méthode d'écriture de `Service`), **et un quatrième seulement au
portage** — la composition attendait le `boot()` alors qu'une application câble ses magasins avant
de démarrer. C'est exactement ce que #91 avançait : un noyau testé contre lui-même se donne raison.

**Le compilateur a refusé un héritage, et son refus disait une vérité de conception.** `ClientKernel`
devait étendre `Service` — TS2416 : `Service.get/set` est la façade du container d'injection,
le registre du kernel est typé et fermé. Deux mécanismes différents sous le même nom. Composition.

## Coûts évidents

- **Quatre cycles rebuild + redémarrage du serveur**, dont un évitable : la barre de débogage a été
  modifiée puis observée à l'écran sans rebuild du cœur, ce qui a fait dire « je ne vois pas les
  modifications » — le dist est ce que Studio consomme, la source ne suffit pas.
- **Trois instruments ont menti** avant d'être corrigés (détail dans `RETEX.md`) : `git diff` muet
  sur un fichier neuf, un filtre de commentaires avalant 4,6 Ko, un gate mesurant un `dist` périmé.
- **Une bascule de 17 tickets pour 2 demandés**, rattrapée en une minute mais évitable en énonçant
  la portée déduite avant d'agir.

## Recommandations

1. **Poser une sonde volontairement fausse avant de croire un « 0 erreur »** — le `tsconfig` d'un
   module de vitrine exclut `frontend` ; dix secondes de sonde ont évité un faux vert publié.
2. **Sur un fichier non commité, `git diff` n'est pas un témoin** — l'assert d'ancre l'est.
3. **Mesurer un contrefactuel plutôt qu'un seuil** : le coût réel d'une brique (+0,57 KB) ne se lit
   pas sur un budget qui passe, il se lit en retirant la brique de l'artefact publié.
