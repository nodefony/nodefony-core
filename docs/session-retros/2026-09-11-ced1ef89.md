# Session retro — 2026-09-11 — ced1ef89

## Focus

Deux tickets pris dans l'ordre du tableau. Aucun des deux n'avait le bon diagnostic dans son
énoncé, et le second a révélé que **rien n'exécutait jamais ce que le générateur produit** — au

## Fait

- **#338 fermé** (`3d94b553`). L'énoncé accusait un glissement de port non répercuté : faux, le
  glissement est publié correctement. La cause est un **double bind que le noyau BSD accepte** —
  une app en production écoute `0.0.0.0:P` alors qu'un tiers tient `127.0.0.1:P`, le bind RÉUSSIT
  (donc ni `EADDRINUSE`, ni glissement, ni refus de `strict`), et le socket le plus spécifique
  reçoit le trafic local. Quatre gestes : refus de readiness sur un port déjà occupé au pré-vol,
  message du pré-vol qui cesse de promettre `auto`, schéma qui accepte `port: 0`, décor e2e qui
  prend un port éphémère.
- **#339 : neuf défauts trouvés**, tous réels, aucun dans l'énoncé (`bf821f25`, `17e2523c`) :
  hook de certificats armé inconditionnellement (→ `EACCES`, **aucune image ne démarrait**) ·
  secrets de service exigés d'un run qui ne sert pas (→ profil `edge` inconstruisible) ·
  `var/databases` en root (`chown` non récursif) · aucune étape de migration dans le compose (→
  `unhealthy` éternel, frontal jamais créé) · port d'hôte passé comme port interne au build nginx ·
  `mime.types` absent (→ **écran noir**, alors que les assets rendent 200) · cas `__Host-` qui lit
  l'environnement du runner et n'a jamais tourné · vitrine qui annonce `admin/admin` en production ·
  `400` nu sur une requête claire au port TLS (redirection `497` posée).
- **#352 ouvert** : `X-Accel-Buffering` absent sur les flux d'événements — repéré en lisant la doc
  nginx, pas en le subissant.
- Le frontal généré gagne compression, cache `immutable` sur les assets empreints, `server_tokens
off`, `sendfile`/`tcp_nopush`/`tcp_nodelay`.

## Coûts évidents

- **Neuf allers-retours de smoke** (~15 min chacun, pack + attw + deux images) parce que chaque
  correctif ne se prouve que sur l'artefact REÇU. Le contournement (copier `dist` dans
  `node_modules` de l'app témoin) ne vaut RIEN ici : l'image réinstalle depuis les tarballs — je
  m'y suis fait prendre une fois.
- **Le décor de la machine** : Redis du dépôt sur 6379, serveur de dev sur 5151/5152, conteneurs de
  test laissés debout par un script mort en silence. Trois faux départs.
- **Un `sleep` interdit par le harnais** m'a fait boucler sur des sondages inutiles pendant les
  longs runs — beaucoup de tours pour peu d'information.

## Recommandations

1. **Le scénario `edge` doit tourner en intégration continue**, pas seulement avant publication.
   Cinq des neuf défauts n'étaient visibles que par lui, et un `release:smoke` ne tourne qu'aux
   releases : un défaut réintroduit demain ne serait vu que dans des semaines.
2. **Un contrôle HTTP dans un banc ne se contente jamais du code de retour.** Type, corps, ou
   les deux. Le `200`/`text/plain` a tenu un écran noir pour vert.
3. **Tout `grep` en substitution de commande prend `|| true`** dans un script `set -euo pipefail`.
   Sans correspondance il rend 1, tue le script hors de `fail`, et laisse le décor debout.
