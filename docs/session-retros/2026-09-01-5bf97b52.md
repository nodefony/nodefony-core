## Coûts évidents

- **Le banc de publication coûte cher à jouer** : ~10 min pour un scénario, ~35 min pour les trois
  (pack + attw des 13 tarballs + 3 `docker build`). Trois passages complets dans la session — un
  rouge, un vert ciblé, un vert complet. Difficile à comprimer : le pack et attw sont en tête, et
  le défaut trouvé n'apparaissait qu'au `docker build`.
- **La sortie de `npm run release:smoke` redirigée dans un fichier est très bufferisée** : le
  journal accusait plusieurs minutes de retard sur l'état réel. J'ai attendu à l'aveugle avant de
  comprendre qu'il fallait regarder les process et les dossiers produits.
- Isoler la cause du `docker build` rouge a demandé **cinq expériences** (sans verrou, `npm ci`,
  verrou écrit dans l'image, `--ignore-scripts`, puis sqlite à l'exécution). Aucune n'était
  superflue : les quatre premières ont chacune éliminé une hypothèse fausse.

## Recommandations

1. **Ne pas conclure sur le mécanisme quand le FAIT suffit à agir.** J'ai cherché un moment
   pourquoi npm se comporte ainsi (version ? plateforme ? `hasInstallScript` ?) alors que les
   expériences avaient déjà borné le remède.
2. **Un banc qui gagne une étape gagne aussi ses effets de bord.** Ajouter l'installation au banc a
   produit un verrou, donc changé ce que `docker build` exécute. Regarder ce qu'une étape LAISSE,
   pas seulement ce qu'elle fait.
3. Le skill `nodefony-release` décrit le cas (b2) du scénario `front` comme inatteignable ; le banc
   l'atteint désormais. À vérifier et recaler — pas corrigé ici, le motif de l'écart n'est pas établi.
