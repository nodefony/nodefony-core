## Recommandations

1. **Mémoire reference — A/B config-via-env** : pour bencher une config pilotée par env, lancer le cluster MANUELLEMENT (spawn detached) + détecter le boot par **poll HTTP** (pas `start.sh`, qui parse le fichier de log → faux négatif si `driver=file`). À capitaliser si re-bench.
2. **A/B perf local = non fiable** : variance de boot **±30%** (8w/6c + load-gen co-localisé) noie l'effet. Reconfirmé fort. Bencher sur **infra dédiée** (1 worker/cœur, load-gen séparé) ou n'en tirer que du directionnel.
3. **Tester un sink avec `close()` juste après `writeOut()`** : c'est ce scénario qui a révélé le bug de durabilité (#inFlight perdu) — un write async + close sync = piège classique.
