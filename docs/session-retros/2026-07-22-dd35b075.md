## Frictions

- **`git checkout -- <fichier>` a effacé du travail non commité** (deux routes de test écrites une
  heure plus tôt) alors que je ne visais qu'à retirer une ligne de sonde. Un `checkout` restaure
  depuis HEAD : il n'annule pas « ma dernière modification », il annule TOUT. Copier le fichier
  avant, ou éditer en place.
- **Le `cwd` du shell a dérivé** : un script python a écrit `test:all` dans le `package.json` de
  mongoose au lieu de la racine. Piège déjà gradué ([[feedback_bash_cwd_drift]]) — il mord encore.
- **J'ai affirmé « `npm run build` racine ne couvre pas le module test » — c'était FAUX.** Turbo le
  détecte bien (`cache miss, executing`). La vraie cause : j'avais modifié le module APRÈS le
  dernier build. Le user a demandé vérification, l'expérience a tranché. Vérifier une conclusion
  d'infra par une manipulation, pas par un raisonnement.
- **Un rapport ne se vérifie qu'en le LISANT** : ses deux derniers bugs (`--load` qui éteint les
  suites, URL de la mauvaise cible) n'ont été vus que parce que le user a lu la sortie et demandé
  « pourquoi 47 sautés ? » et « je ne vois pas les URL ». Un affichage juste en apparence peut
  décrire un run qui n'a pas eu lieu.
- **Cinq échecs successifs attribués à tort** à la charge, puis à la DB, puis à un flake : c'était à
  chaque fois une cause structurelle différente et réelle. Un échec intermittent n'est pas un flake
  tant qu'on n'a pas lu son message exact — ici le `CRITIC` du kernel disait tout.
